# Проверка оформления по страницам 5–7 PDF

Проверена актуальная версия учебного репозитория, включая `src`, `tests`
и `scripts`. Файлы сайта выдачи и внешний ZIP в этот репозиторий не входят.

```sh
make check
make test
```

| Правила | Проверка | Результат |
| --- | --- | --- |
| С1–С5 | README.md, .gitignore, src, tests, run.sh и Makefile | Есть |
| С6 | Заголовки всех коммитов — Conventional/Scoped Commits | Соответствуют |
| Г1 | Архивы среди `git ls-files` | Нет |
| Г2 | Бинарные файлы среди `git ls-files` | Нет |
| Г3 | pyc/pyo, __pycache__, виртуальная среда | Не отслеживаются |
| Г4 | Артефакты сборки, пакеты, jar, сгенерированные SVG | Исключены |
| Г5 | .idea, .vscode | Не отслеживаются |
| Р1 | Все отслеживаемые текстовые файлы <= 1000 строк | Выполнено |
| Р2, Р6 | Python <= 80 символов в строке | Выполнено |
| Ф1 | Python-функции <= 40 строк | Не более 40 |
| А1 | <= 7 аргументов | Выполнено |
| К1 | Docstring у функций | Есть |
| Ц1 | Сложность <= 10, включая boolean/ternary/comprehension | Максимум 10 |
| М1 | Числовые литералы в операндах сравнений | Нет |
| И1 | snake_case/CamelCase/UPPER_CASE | Соответствуют |

Пункты для JavaScript, Kotlin, Rust, Java, C#, Go неприменимы: этих языков
в учебном репозитории нет. Методов `setUp` и `tearDown` нет: конфигурация создаётся helper-методом,
HTTP-сервер — через `prepare_server()` с регистрацией `addCleanup`.
Проверка имён не делает исключений для методов unittest.

Проверка сложности считает базовый путь и ветвления AST: if, ternary,
циклы, except, assert, дополнительные boolean-операнды, генераторы и их
фильтры. Проверка имён покрывает объявления, аргументы и присваивания.
Числа в индексах, например `a[0] < b[0]`, не являются порогами сравнения.
Четыре регрессионных теста подтверждают обнаружение нарушений аудитором.

После первого решения добавлен отдельный исправляющий коммит:
уменьшена сложность функций, введены именованные константы для сравнений,
расширен аудит. Сгенерированные SVG перенесены на страницу выдачи. Текстовые
примеры PlantUML и результаты сравнений сохранены как документация работы.

Внешний ZIP сохраняет каталог `.git` для истории этапов. Служебные объекты
самого Git не считаются отслеживаемыми бинарными файлами проекта.
Публичный репозиторий пользователя существует, но проверенная исправленная
история ещё не отправлена в GitHub: требуется публикация новой ветки
по `windows-publication.md`. Сайт служит для скачивания ZIP и не заменяет это требование.

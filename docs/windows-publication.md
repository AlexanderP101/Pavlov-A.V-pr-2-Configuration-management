# Как отправить исправленную работу с Windows

Причины отказа на скриншоте:

- С2: при загрузке файлов через браузер пропал скрытый `.gitignore`.
- С6: вместо истории этапов появились `Initial commit`, `Delete README.md`,
  `Add files via upload`. Новый обычный коммит не исправляет старые сообщения.
- Г3: после запуска Python были загружены файлы `__pycache__/*.pyc`.
- И1: проверяющий отклоняет методы unittest с именами `setUp`, `tearDown`.
  Теперь таких определений нет; фикстуры работают через snake_case и cleanup.

## Важно: распаковать в НОВУЮ папку

Скачайте свежий ZIP с сайта. Распакуйте в новую пустую папку, не поверх старой.
Внутри `variant18` должны быть `.gitignore` и скрытый каталог `.git`.
В архиве уже сохранена история этапов с правильными сообщениями.
Не загружайте файлы на GitHub через кнопку Upload files.

Установите Git for Windows и Python 3.11+. Откройте PowerShell в `variant18`.

```powershell
Get-Item -Force .gitignore
Get-Item -Force .git
git log --oneline --reverse
$env:PYTHONPATH = "src"
py -B -m unittest discover -s tests -v
py -B scripts/check_style.py
```

Тесты должны завершиться `OK`, проверка оформления — также `OK`.
Для обычного запуска на Windows:

```powershell
.\run.bat examples/acyclic.toml --stage 1
```

## Публикация без удаления старой истории GitHub

Публикуем исправленную историю в НОВУЮ ветку `variant18-fixed`.
Она не включает три неправильных коммита из прежней ветки.
Команда не выполняет merge и не перезаписывает старую ветку.
Выполнить из НОВОЙ распакованной папки:

```powershell
git push https://github.com/AlexanderP101/Pavlov-A.V-pr-2-Configuration-management.git HEAD:refs/heads/variant18-fixed
```

При необходимости Git откроет вход в ваш аккаунт GitHub.
Если ветка уже существует и Git отказывает в обновлении, не используйте
`--force`: выберите новое имя, например `variant18-fixed-v2`.

Можно выполнить тот же процесс скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File .\publish.ps1
```

На странице проверки укажите прежний URL репозитория и ОБЯЗАТЕЛЬНО в поле
«Хеш коммита или имя ветки» введите `variant18-fixed` (либо выбранное имя).
Если оставить поле пустым, проверяться снова будет старая главная ветка.
Другой вариант — сделать исправленную ветку главной в настройках GitHub.

В существующей старой истории остаются неправильные коммиты. Простое
добавление `.gitignore` не уберёт уже отслеживаемые `.pyc` и не исправит С6.
Поэтому не копируйте только новые файлы поверх старого репозитория и не
сливайте старую ветку в исправленную перед проверкой.

GitHub не был изменён из среды помощника: доступ на запись недоступен.
Архив содержит подготовленный и проверенный результат для публикации вами.
